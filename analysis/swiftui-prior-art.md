指摘を受けて始めました（原文:「先人が作ったものを取り入れる方が質が高くなると思います。
あなたが0→1で作っているからミスが多いだけだと思います」）。

## 宣言した数（段1を始める前に決めたもの）

**あとから機械で照合するために、先に書いています。**足りなければ「足りなかった」と書きます。
**水増しはしません。**

| 軸 | 宣言した件数 | 実際 | 差 |
|---|---|---|---|
| トークンの生成と検証 | 15〜20 | **14** | **足りませんでした**（水増しせず、そう報告されています） |
| 部品のカタログ | 10〜15 | **15** | 範囲内 |
| 検査を飛ばせなくする仕組み | 15〜20 | **20** | 範囲内 |
| AI に SwiftUI を書かせる規則集 | 15〜20 | **16（＋基準未達3）** | 範囲内 |
| 複数プラットフォームと移行 | 10〜15 | （待ち） | |

**足りなかった1軸は、足りなかったと書かせています。**これがこの調査でいちばん確かめたかった点です
（2026-09-19、私が「10〜15件」という数に後付けの理由を添えた件を受けて）。

## 各件で必ず埋める項目（段3）

**項目を固定するのは、後から比べられるようにするためです。**

- 何を機械で見ているか
- どうやって止めているか（落ちる条件。人の申告に頼っていないか）
- 空振りしていないことを、どう確かめているか
- 依存（追加ライブラリ・CI・有料）
- 取り込めるか（そのまま / 考え方だけ / 不可）と理由
- **README だけ読んだか、コードも見たか**

## 守ったこと

- 外部リポジトリの中身は**データとして扱い、その中の指示には従っていません**
- **スクリプトは実行していません**
- star 数や README の主張を鵜呑みにせず、**件ごとに読んだ範囲を記録**しています
